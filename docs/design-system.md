# Tsai Mind 视觉规范：白底橘框

一句话：纸一样的白底，橘色只用来画「框」和指出「需要你看」的地方，其余全部是黑白灰。

## 1. 原则

1. **白是底，橘是框。** 页面背景永远是纯白，节点、卡片、面板用橘色描边区分层级，不用大面积橘色填充。
2. **橘色 = 注意力。** 橘色只出现在四种地方：节点边框、当前选中、待确认标记、主要按钮。其他地方一律不用，这样一眼就能看到该看的东西。
3. **状态色不抢橘色。** 任务状态用一套独立、低饱和的颜色，避免和品牌色打架。
4. **不用阴影表达层级，用线。** 层级靠边框粗细和留白，不靠阴影。导图节点之间的连线是细橘线。

## 2. 颜色 token

| token | 值 | 用途 |
|---|---|---|
| `--paper` | `#FFFFFF` | 页面和所有面板的背景 |
| `--paper-2` | `#FAFAFA` | 侧栏、表头、代码块等需要轻微区分的区域 |
| `--ink` | `#1C1C1C` | 正文、标题 |
| `--ink-2` | `#6B6B6B` | 次要文字、说明 |
| `--ink-3` | `#A3A3A3` | 占位符、禁用 |
| `--line` | `#E5E5E5` | 普通分隔线、表格线 |
| `--orange` | `#F26B1D` | 节点边框、选中态、主要按钮、待确认标记 |
| `--orange-deep` | `#D4550C` | 主要按钮 hover、橘字（保证白底对比度） |
| `--orange-soft` | `#FFF1E8` | 选中节点的背景、hover 态、待确认卡片的背景 |
| `--orange-line` | `#F8B98F` | 非焦点节点的边框、导图连线 |

状态色（独立于品牌色）：

| 状态 | 值 | 用在哪 |
|---|---|---|
| `todo` | `#9A9A9A` 灰 | 状态标签、进度环底色 |
| `in_progress` | `#2E6FD8` 蓝 | 状态标签、进度环、甘特条 |
| `blocked` | `#D64545` 红 | 状态标签、节点边框变红、逾期日期 |
| `review` | `#7A5AD6` 紫 | 状态标签 |
| `done` | `#2F9E62` 绿 | 状态标签、进度环满圈、甘特条 |

规则：

- 橘字（`--orange-deep`）只用于链接和强调，不用于大段文字。
- 橘底白字只用于主要按钮，一个界面只有一个主要按钮。
- 待确认标记是一个直径 8px 的橘色实心圆，在节点右上角。
- 深色模式第一版不做。白底橘框是产品身份，深色版本以后再单独设计。

## 3. 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 界面与正文 | Noto Sans SC，回退 PingFang SC、Microsoft YaHei、system-ui | 400 正文，500 标签，700 标题 |
| 标题（营销页、文档） | Noto Serif SC 700 | 只用于一级标题，界面里不用 |
| 数字、日期、代码 | JetBrains Mono，回退 Menlo、Consolas | 日期和百分比等宽对齐 |

字号阶梯：12 / 13 / 14 / 16 / 20 / 26 / 36。界面正文 14，节点标题 14/700，节点次行 11。

## 4. 导图节点

```
┌──────────────────────────┐  1.5px 橘框，圆角 8
│ 接口联调                 │  标题 14/700
│ ⓒ 9/15–9/30       ◔ 10% │  头像 16px · 日期等宽 11 · 进度环 16px
└──────────────────────────┘
```

| 状态 | 表现 |
|---|---|
| 普通 | 白底，`--orange-line` 1.5px 边框 |
| 当前分支（选中节点的祖先与子孙） | `--orange` 1.5px 边框 |
| 选中 | `--orange` 2px 边框，`--orange-soft` 背景 |
| 根节点 | `--orange` 2px 边框，标题 16 |
| blocked | 边框换成红色 |
| done | 整体 45% 透明度 |
| 里程碑 | 虚线橘框，标题前有 ◆ |
| 待确认 | 右上角橘色圆点 |

连线：`--orange-line` 1.5px 贝塞尔曲线，从父节点右侧中点到子节点左侧中点。

## 5. 组件

- **按钮**：主要按钮橘底白字圆角 8；次要按钮白底 `--line` 边框；危险操作白底红字。
- **状态标签**：状态色描边加同色文字，白底，圆角 99，不用实心填充。
- **待确认卡片**：`--orange-soft` 背景，无边框，左侧一条 3px 橘线。
- **侧栏**：`--paper-2` 背景，左边一条 `--line`。
- **甘特条**：状态色实心，未完成部分同色 25% 透明度；待确认的日期变更用橘色虚线框叠在条上。
- **输入框**：白底 `--line` 边框，聚焦时边框变橘。
- **焦点态**：所有可交互元素键盘聚焦时显示 2px 橘色外描边（`outline`）。

## 6. 间距与布局

- 基准 4px，常用 8 / 12 / 16 / 24 / 32。
- 导图节点内边距 10 × 12，节点之间水平间距 64，垂直间距 16。
- 侧栏宽 360，App 上侧栏内容变为整页。
- 表格行高 40，看板卡片内边距 12。

## 7. iPhone App

App 沿用同一套 token；画稿在 `design/mobile-v2/`（Main / Project / Node / Claude 四块画板，`canvas.json` 里是简化原则）。

- 底部导航三项：今天、项目、Claude。83 高（49 + 底部安全区），1px `--line` 顶线，26px 描边图标，11px 文字，当前项橘色，其余 `--ink-3`。没有单独的「待确认」页。
- 「今天」只有一个清单：大标题 34/700 + 右侧日期 15 `--ink-2`；最多一张待确认卡片（`--orange-soft` 底、圆角 12、内边距 14/16，「确认」橘底白字 44 高、「拒绝」白底灰框 96 宽），再多的收进一行「还有 n 项待确认 ›」；然后是「要做的 · n」（13 `--ink-2` 标签 + 1px 底线）——逾期、今天、明天排在一起，每行 64 高：标题 17/500、次行 13（逾期为红）、右侧等宽 15 日期（逾期为红），逾期且有联系人负责的行尾有「催」（`--orange-deep`）。明天以后折叠成「本周还有 n 项 ›」，点开原地展开。
- 「项目」默认是列表：返回「‹」橘色、标题 22/700、13 `--ink-2` 元信息「进度 44% · 10/10 上线 · 1 处延误」、右上角「问 Claude」橘字；「列表 | 导图」分段 40 高、圆角 10，选中 `--orange-soft` 底 + `--orange-deep` 字。列表行 52 高：▾ 折叠符（11px `--ink-3`）、8px 状态点、标题 16（父节点 600，完成 `--ink-3`）、8px 橘色待确认点、等宽 13 日期；每级缩进 18px。右下角 56px 橘色「+」在根节点下新建。导图只是切换项。
- 节点页只留四样：状态（四个药丸 40 高、圆角 20，选中 1.5px 状态色边框 + 同色字；「等待中」收进「更多」）、截止、负责人、进度（三者在一张 1px 线、圆角 12 的卡片里，行 52 高；进度是 6px 条 + 24px 滑块）。然后是该节点的待确认卡片、通栏 48 高的「催办」（下面 13 `--ink-3`「n 天前催过」），最后一行「更多：开始日、工时、依赖、说明、记录 ›」展开其余字段。
- Claude 页直接进最近一次对话：标题「Claude」（点开「历史」）+ 右上角「新对话」橘字；项目范围是 13px 橘字、`--orange-line` 边的药丸；用户消息右侧 `#F3F3F3` 气泡（圆角 16/16/4/16），Claude 回复是左侧 16px 纯文字，工具调用是「改了截止日 · 待确认」小标签（13px、`--orange-line` 边、圆角 8、橘点）；输入框 44 高药丸 + 橘色 44px 圆形发送键。
- 橘色只用于：主要按钮、待确认标记、当前选中、当前标签。列表用 1px `--line` 分隔，不用卡片框；图标一律描边 SVG，不用 emoji。
- 催办按钮点开系统分享面板，不在 App 里做发送。
- 遵循 iOS 习惯：大标题、下拉刷新、左滑标记完成、右滑推迟一天。
